麦当劳的早餐券按天发放、只在当天 05:00–10:29 有效。 真正的问题不是"早上吃什么"，而是——这件事根本就不该在早上处理。 这个 Skill 把它挪到前一晚做完。

看本周安排表

它做的事，就一件

在你的睡前，把明早那一单准备好。下面是一次完整的演示（模拟数据，不会真实下单）。演示里的所有偏好，都是它从该用户自己的订单里学出来的——换一个人用，学出来的就是另一个人的习惯。

点上方按钮开始

那张图：本周早餐安排表

它不是给你一张菜单，而是给你一张排好的表——哪天用哪张券、吃什么、多少钱、状态如何。这张图由真实 MCP 数据生成（演示数据已脱敏）。

核心不是"推荐"，是取交集：只按券推会推给你不爱吃的，只按习惯推会浪费掉当天的券。两者取交集，才是"既对味、又省钱"的那一单。

它是怎么做到的

全程只编排麦当劳官方 MCP 的工具，Skill 本身不含任何连接与凭证。

1

对齐时间

now-time-info 取服务端时间，确定"明天"是哪一天。

2

学习惯

order-list 拿单号，逐单 query-order 读定制文本，归纳主餐偏好、固定搭配与常驻特制。

3

领券 → 筛券

available-coupons 看有什么可领 → auto-bind-coupons 一键领齐 → query-my-coupons 筛出目标日有效的那张。

4

拉次日菜单

query-meals 带 reservationDate，直接返回次日早餐品类，并确认券对应商品仍在售。

5

取交集

习惯 ∩ 券适用商品，再用 query-meal-detail 解析特制项与套餐可替换项。

6

试算

query-store-coupons 取券的 couponId/couponCode，calculate-price 算价并取回取餐方式。

7

建单

create-order 建预约单，返回订单号与支付链接。券未到生效时段时，等它生效后再下单，确保券真的用得上。

它是真的跑通过的

下面这些不是设想，是在真实麦当劳 MCP 服务上验证过的。

非早餐时段，能查到次日早餐菜单

同一门店、同一时刻，带上目标日参数返回的是早餐品类，不带则返回当前时段菜单。这是"提前一晚"能成立的前提。

特制能跟着预约单一起传下去

历史订单里的定制（如"不要芝士""不要生菜"）可以还原成下单参数，与预约日期一起提交并正确计价。

门店的早餐时段可查、可预约

门店会返回是否支持预约，以及接下来每一天的可预约时段，取餐时间据此校验。

边界与诚实

支付必须由你本人完成

麦当劳官方不提供免密代付。本项目只创建订单并返回支付链接，不会、也不能替你付款——所以它的说法永远是"订单已创建，请在 X 分钟内完成支付"。

数据以官方为准

餐品信息、价格及供应状态以麦当劳官方渠道的实时结果为准。

本页是演示

所有内容均为虚构演示数据，不会真实下单，也不需要你提供任何 Token 或账号信息。
